Benchmarks and Methodology

Atlas publishes benchmark results for accuracy, token use, latency, language compatibility, and agent workflows. Use this page to interpret those numbers correctly — every result is a dated measurement under stated conditions, not a general guarantee.

Open the Atlas benchmark explorer

What 0.1.55 adds to the evidence, a labelled relevance benchmark with a regression gate and the multi-language agent benchmark, is summarised in the 0.1.55 release notes.

How to Read a Result

Work through this checklist before comparing tools or quoting a number — a result you cannot place in it is not evidence:

  1. Identify the setup. Atlas and baseline tool versions, repository URL and pinned commit, language and query set.
  2. Identify the conditions. Hardware and operating system, cold-cache or warm-cache state, repeat count and aggregation method.
  3. Identify the scoring. The accuracy oracle or reviewer, and the token measurement method (provider-reported usage versus a documented estimate).
  4. Identify the failure handling. How failed and timed-out cases were counted. A mean that silently drops failures is not comparable to one that scores them.

Evidence Categories

Keep categories separate — do not combine them into one unsupported headline:

  • Compatibility: whether a format indexes successfully
  • Correctness: precision, recall, or F1 against an oracle
  • Latency: elapsed index or query time under stated cache conditions
  • Token use: measured model/tool usage or a documented estimate
  • Agent workflow: end-to-end behavior for a pinned assistant and task set

Provenance, stated plainly:

  • The Atlas cells ran on develop working-tree builds made during the campaign (six builds, each named per language in the artifacts); the changes merged to develop the same night and ship in 0.1.55. Java's Atlas cells came from two of those builds (31 and 7 cells); the later build only answered cells re-run after a timeout or provider error.
  • Cells that timed out or hit provider errors were re-run; every final cell is ok. A run that names no function is scored F1 0, not dropped (25 graph-tool runs on codex across the eight languages).
  • The JavaScript and TypeScript question sets were regenerated on 2026-10-29 after the truth generator stopped counting references passed as values (for example bind(…)) as calls; the stored answers of every mode were re-scored against them. Sixteen C++ no-tool answers were re-scored when the scorer learned to strip :: qualifiers and a destructor's ~. Every re-score is listed, cell by cell, in the per-language artifact.

Per-run records: data/raw/AGENT_TOKEN_BENCH_<LANG>_20261028.json for GO, PYTHON, C, JAVA, CPP, JAVASCRIPT, TYPESCRIPT and RUST; question sets: agent-bench/QA_SET_<lang>.json (QA_SET_logrus.json for Go).

The gate. 159 frozen thresholds, each the measured develop baseline minus a margin (0.03 pooled precision/MRR/recall/entity-first, 0.05 pooled refusal/safe, 0.06 per corpus, 0.09 per-corpus safe, each widened to one query's worth for small sets); all 159 hold. Two back-to-back runs on fresh stores: 16 of 724 ranked lists differ, none at rank 1, gated drift 0. The gate catches regressions; it does not certify that retrieval is good — the baseline encodes today's defects, published as follow-ups:

  • F1 — Question-template words are ranked as search terms (stopword pollution)
  • F2 — Entity-first routing exists for “what calls”, not for “where is … defined”
  • F3 — A case-exact whole-name match does not outrank case-folded or partial matches
  • F4 — Non-code facts outrank code for code-shaped questions
  • F5 — search refuses real identifiers inside a question (false off-topic)
  • F6 — code_query's relevance floor (#60) grounds on generic words that happen to be symbol names, and keeps citations retrieved only by stopwords
  • F7 — context never refuses and always ships a ~30 KB bundle
  • F8 — Tied results ordered by store insertion order — fixed on develop by #135, kept as a regression control
  • F9 — Graph packing puts test callers ahead of the error types a question names
  • F10 — A vendored test framework answers generic questions (fixture pollution)

Measured 2026-10-29 on atlas v0.1.52-700-g1a75deae (develop 3790ba95 plus the benchmark; no ranking code changed), macOS arm64, 80.8 s. Repro, likely cause and acceptance for every finding: relevance-bench/RESULTS.md; per-query rows and every gate verdict: RELEVANCE_BENCH_20261029.json.

Reproduce It Yourself

Every published number is reproducible from committed artifacts — verify before you cite:

  • Processed site data (site-data.json)
  • Raw benchmark artifacts (data/raw)
  • Evidence manifests
  • Agent benchmark kit (agent-bench/)
  • Relevance benchmark kit (relevance-bench/)

The agent suite ships with the pinned commit, frozen gopls question set, and isolation flags baked in:

python3 agent-bench/agent_token_bench.py \
  --setup \
  --agents auto \
  --modes atlas,graphify,baseline \
  --qa-set agent-bench/QA_SET_logrus.json \
  --workdir agentbench-work

Any other language: pass its question set, for example --qa-set agent-bench/QA_SET_rust.json --workdir agentbench-rust. The harness clones the commit pinned inside the set.

The relevance benchmark drives the atlas binary you have installed and fetches the three pinned corpora:

python3 relevance-bench/relevance_bench.py --atlas "$(command -v atlas)" \
  --work relevance-work \
  --results-json my-relevance.json --results-md my-relevance.md

Read agent-bench/README.md for prerequisites, expected external cost, pinned inputs, and interpretation. Per-run records are in AGENT_TOKEN_BENCH_PUBLIC_20261029.json (the two earlier logrus runs beside it) and the per-language AGENT_TOKEN_BENCH_<LANG>_20261028.json files; relevance-bench/README.md covers the relevance harness.

Important Limitations

  • Fixture results do not prove production-repository accuracy.
  • One repository does not establish performance across a language.
  • Different assistants may consume the same MCP result differently.
  • Estimated tokens are not equivalent to provider-reported token usage.
  • Warm-cache query latency is not cold-start installation or indexing time.
  • Language support and result quality can differ by syntax and framework.

Per-language support levels behind these results are summarized in Supported Languages and Formats.

Reporting a Comparison

If you publish your own comparison, include everything a reader needs to reproduce it:

  • exact commands
  • raw machine-readable output
  • all failed and timed-out cases
  • environment metadata
  • evidence limitations
  • the Atlas release tag and checksum

Benchmark results are dated measurements under published conditions — not a guarantee for every repository, machine, language, or assistant.
