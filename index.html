Atlas — local code intelligence for developers and AI agents

Atlas indexes repositories locally and returns focused, source-grounded context about symbols, callers, references, routes, and change impact through CLI, MCP, and HTTP.

GitHub · Download v0.1.50 · Benchmark data (JSON)

Get started

Install with brew install --cask aziron-ai/atlas/atlas or from the public npm registry with npm install -g @aziron/atlas. The installation guide also covers the authenticated GitHub Packages coordinate. Then run atlas index ., inspect readiness with atlas status, and preview assistant setup with atlas bootstrap --dry-run.

Headline results — Benchmark & field comparison — refreshed at fc3b875 (2026-08-05)

  • 3.17× fewer answer tokens than the graph tool, pooled across a 7-repository matrix (26 queries both tools answered). Per-language mean 5.06×, median 3.66×, worst language cpp at 1.41×.
  • And a better answer: caller-F1 0.865 vs 0.541 — 1.6× — scored by claude-haiku-4-5-20251001 over 222 cells / 666 model calls on 37 constructed-truth fixtures.
  • The shipped default matches the maximum-detail level exactly (F1 0.865 both) at 9.6× fewer tokens — 23.9 vs 230.1. 32 of 37 languages score a perfect 1.000.
  • Inside a real agent (sirupsen/logrus, gopls call-hierarchy ground truth, 19 questions): F1 0.995 with Atlas on both the claude and codex harnesses.
  • Queries run 4.12× faster than the graph tool on the same matrix (mean of the seven per-repository ratios); warm-serve explain lands between 1.6 and 14.9 ms.
  • Corroborated by an independent Linux re-run: 32/37 languages fixture-perfect, gopls-truth F1 0.900. That leg ran on Linux 6.12.54-linuxkit aarch64; it has no graph-tool binary, so it publishes no competitor ratio.

Retracted claims

  • 36× fewer query tokens → 3.17× pooled / 5.06× per-language mean (measured against a build that answered with a 2-token placeholder)
  • 17× faster queries → 4.12× (matrix) (same stub comparison; the honest figure is a same-host, same-run measurement)
  • +40% answer accuracy → 1.6× the F1 (0.865 vs 0.541) (a percentage of an F1 is not a meaningful unit; the ratio and both raw values are published instead)
  • 2.3× faster cold index / 14× faster incremental / 7.9× more call edges / 100.2% AST coverage → withdrawn, not restated (not re-measured at this commit. A number nobody re-ran is not evidence.)

Language maturity ladder — 40 code languages

Levels reflect validation depth, not just support — an L2 language still indexes and searches; it simply has not reached verified call-graph resolution. A language moves DOWN when its evidence does: dart came off L5 this refresh. Atlas also indexes ~24 content formats (JSON, YAML, HTML, PDF, …) for search.

The verifier re-run measures .8631 against the same reference server on the same pinned repository. Dart returns to L4 until `toString`-scale fan-out and `package:` re-export families bind. We publish the retraction rather than the flattering number.

Requalified. This page previously asserted “native F1 1.000 each on the Linux saturation run” for Bash, Blade, BYOND, EJS, Objective-C, Pascal, PowerShell, Razor, Ruby. The saturation branch that produced that claim never merged. Re-measured at this commit, the fixture is perfect for 4 of the nine and returns an empty caller list for the rest. The site-wide fixture score is 32/37, not 37/37. Ruby is a special case and is now L5 on LSP-truth (F1 1.000 against solargraph on rack, 9 symbols). Its 0.000 on the fixture is DESIGNED: the fixture's callers are top-level, and the binder refuses to attribute a top-level call to an owner it cannot prove rather than guessing one. Ruby's promotion cites the LSP lane and never the fixture.
