Atlas — local code intelligence for developers and AI agents

Atlas indexes repositories locally and returns focused, source-grounded context about symbols, callers, references, routes, and change impact through CLI, MCP, and HTTP.

GitHub · Download v0.1.55 · Benchmark data (JSON)

Get started

Install with brew install --cask aziron-ai/atlas/atlas or from the public npm registry with npm install -g @aziron/atlas. The installation guide also covers the authenticated GitHub Packages coordinate. Then run atlas index ., inspect readiness with atlas status, and preview assistant setup with atlas bootstrap --dry-run.

Headline results — Benchmark & field comparison — refreshed at fc3b875 (2026-08-05, shipped in v0.1.51)

  • 3.17× fewer answer tokens than the graph tool, pooled across a 7-repository matrix (26 queries both tools answered). Per-language mean 5.06×, median 3.66×, worst language cpp at 1.41×.
  • And a better answer: caller-F1 0.865 vs 0.541 — 1.6× — scored by claude-haiku-4-5-20251001 over 222 cells / 666 model calls on 37 constructed-truth fixtures.
  • The shipped default matches the maximum-detail level exactly (F1 0.865 both) at 9.6× fewer tokens — 23.9 vs 230.1. 32 of 37 languages score a perfect 1.000.
  • Inside a real agent (sirupsen/logrus, gopls call-hierarchy ground truth, 19 questions, 2026-10-29): F1 0.996 with Atlas on both the claude and codex harnesses.
  • The same harness in 8 languages (2026-10-28): Atlas beats the no-tool baseline and the graph tool on both accuracy and tokens in 16 of 16 agent × language cells.
  • The tool alone, against each language's LSP server (2026-10-29): callers F1 Go 0.996, Python 0.965, C 1.000, Java 0.858, C++ 0.935, JavaScript 0.940, TypeScript 0.950, Rust 0.991.
  • Queries run 4.12× faster than the graph tool on the same matrix (mean of the seven per-repository ratios); warm-serve explain lands between 1.6 and 14.9 ms.
  • Corroborated by an independent Linux re-run (2026-08-05): 32/37 languages fixture-perfect, gopls-truth F1 0.900. That leg ran on Linux 6.12.54-linuxkit aarch64; it has no graph-tool binary, so it publishes no competitor ratio.

Retracted claims

  • 36× fewer query tokens → 3.17× pooled / 5.06× per-language mean (measured against a build that answered with a 2-token placeholder)
  • 17× faster queries → 4.12× (matrix) (same stub comparison; the honest figure is a same-host, same-run measurement)
  • +40% answer accuracy → 1.6× the F1 (0.865 vs 0.541) (a percentage of an F1 is not a meaningful unit; the ratio and both raw values are published instead)
  • 2.3× faster cold index / 14× faster incremental / 7.9× more call edges / 100.2% AST coverage → withdrawn, not restated (not re-measured at this commit. A number nobody re-ran is not evidence.)

Gate: 159 of 159 frozen thresholds hold. Two back-to-back runs on fresh stores: 16 of 724 ranked lists differ, none at rank 1, gated drift 0 over all 159 thresholds (RESULTS.md, F8). The gate catches regressions; it does not certify that retrieval is good — the baseline encodes today's defects, listed below as follow-ups. When a fix lands, the gate is re-frozen from a reviewed run so it ratchets.

  • F1 — Question-template words are ranked as search terms (stopword pollution)
  • F2 — Entity-first routing exists for "what calls", not for "where is … defined"
  • F3 — A case-exact whole-name match does not outrank case-folded or partial matches
  • F4 — Non-code facts outrank code for code-shaped questions
  • F5 — search refuses real identifiers inside a question (false off-topic)
  • F6 — code_query's relevance floor (#60) grounds on generic words that happen to be symbol names, and keeps citations retrieved only by stopwords
  • F7 — context never refuses and always ships a ~30 KB bundle
  • F8 — Tied results ordered by store insertion order (FIXED on develop by #135 (kept as a regression control))
  • F9 — Graph packing puts test callers ahead of the error types a question names
  • F10 — A vendored test framework answers generic questions (fixture pollution)

Levels reflect validation depth, not just support — an L2 language still indexes and searches; it simply has not reached verified call-graph resolution. A language moves DOWN when its evidence does: dart came off L5 this refresh. Atlas also indexes ~24 content formats (JSON, YAML, HTML, PDF, …) for search.

Requalified. This page previously asserted “native F1 1.000 each on the Linux saturation run” for Bash, Blade, BYOND, EJS, Objective-C, Pascal, PowerShell, Razor, Ruby. The saturation branch that produced that claim never merged. Re-measured at this commit, the fixture is perfect for 4 of the nine and returns an empty caller list for the rest. Its 0.000 on the fixture is DESIGNED: the fixture's callers are top-level, and the binder refuses to attribute a top-level call to an owner it cannot prove rather than guessing one.
